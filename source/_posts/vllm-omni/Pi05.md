# Pi0.5：vLLM-Omni 集成与优化路线图

π0.5 这份 roadmap 可以记成：**跑通 → 共用 → 单请求提速 → 接入框架 → 批量执行 → 动态调度**。[路线图 #6867](https://github.com/vllm-project/vllm-omni/issues/6867)
- **F1：跑通功能**——接入 π0.5，保证模型结果和服务接口正确。
- **F2：共用结构**——提取 π0 / π0.5 真正共有的模块，减少重复代码。
- **S0：减少框架开销**——定位并优化排队、调度、分发、结果返回等模型之外的耗时。
- **R0：单请求提速**——用 CUDA Graph、融合 kernel、静态 buffer 优化 BS=1。
- **P0：探索 BF16**——评估局部使用 BF16 的速度收益和数值误差。
- **R1：接入公共组件**——评估并复用框架的编译、attention、算子和运行机制。
- **R2：执行已有 batch**——支持 B=1/2/4/8/16/32，验证正确性和吞吐收益。
- **D0：按步动态调度**——让 scheduler 看见每个 denoise step，在步间加入或移除请求，探索 continuous batching。
